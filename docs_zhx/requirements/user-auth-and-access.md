# 基金雷达用户认证、数据归属与权限需求

## 1. 目标与范围

本次为 L2 改造：浏览器必须先登录才能读取基金、个人关注、提醒或持仓；前台用户端与后台管理端分区展示。认证、资源授权和个人数据范围均由 Java 服务端完成，Vue 仅根据服务端返回的权限改善导航体验。

手机号只作为当前阶段的登录标识，尚未接入短信验证，不能表述为实名或已核验身份。系统不采集支付宝账号、验证码、Cookie、支付凭证，也不提供交易操作。

## 2. 账户生命周期

1. 登录只提交中国大陆 11 位手机号和密码，手机号格式为 `^1[3-9]\d{9}$`。
2. 登录只校验既有账户；手机号不存在、密码错误、账户停用和缺少密码哈希均返回同一认证失败，不创建或覆盖账户。
3. 新用户必须进入注册页，确认中国大陆手机号、设置并再次确认 6 至 20 位密码后，服务端在同一事务中创建状态为 `ACTIVE`、角色为 `FUND_USER` 的账户并建立会话；重复注册返回 `409/ACCOUNT_ALREADY_EXISTS`。
4. 用户不能自行选择角色、找回密码或更换手机号。系统管理员可人工重置密码、调整角色、启停账户；重置密码、角色变更和停用都会撤销目标全部会话。
5. 首位系统管理员只由受保护的部署环境变量创建。具体手机号和密码不得出现在代码、文档、日志、测试或 Git 提交中。

## 3. 角色与权限

| 角色 | 用户端能力 | 后台能力 | 明确禁止 |
| --- | --- | --- | --- |
| `FUND_USER`（基金用户） | 基金、本人关注、本人提醒、本人持仓 | 无 | 用户管理、同步、他人持仓 |
| `DATA_OPERATOR`（数据运营） | 同基金用户 | 查看/发起同步、查看运行状态 | 用户账户管理、历史关注迁移、他人持仓 |
| `SYSTEM_ADMIN`（系统管理员） | 全部用户端能力 | 全部当前与后续权限；含用户管理、历史关注迁移、查看指定用户持仓 | 无业务权限限制，但所有高风险动作审计 |

菜单权限不是安全边界。服务端分别校验基金读取、本人读写、同步读取/启动、用户读取/管理、历史关注迁移、他人持仓读取等资源权限。

## 4. 个人数据归属

- `watchlist_item`、`alert_rule`、`portfolio_snapshot` 均通过认证上下文中的 `user_id` 读取和写入；浏览器不得传入可控 `userId` 作为个人数据范围。
- 系统管理员可通过独立后台接口读取指定用户最新确认持仓，供人工核对金额；数据运营无此权限。
- 旧固定本机账户仅保留为待归属历史记录。管理员在浏览器二次确认并提交 `confirmed=true` 后，才可迁移其关注列表至一个已启用账户；提醒和持仓不会被自动迁移。

## 5. 验收标准

1. 未登录读取基金、关注、提醒、持仓、同步、运行状态均返回 `401/AUTHENTICATION_REQUIRED`。
2. 未注册手机号登录返回 `401/INVALID_CREDENTIALS` 且不创建账户；显式注册新手机号会生成基金用户并建立会话，重复注册返回 `409/ACCOUNT_ALREADY_EXISTS`。
3. 数据运营访问用户管理或他人持仓返回 `403/ACCESS_DENIED`；系统管理员可完成对应操作。
4. 用户 A 无法通过页面或直接 API 读取/修改用户 B 的关注、提醒或持仓。
5. 对外响应、日志和审计中不出现完整手机号、密码、原始会话令牌或 CSRF 值。

## 6. 2026-08-27｜v1.1 显式注册与密码规则调整

因登录时输入错误手机号会被无感建号，取消登录建号机制，改用带确认密码的独立注册页。当前仍未接入短信验证，因此注册只确认用户主动填写，不代表系统已验证手机号归属。密码规则调整为 6 至 20 位字符，拒绝纯空白密码，不再要求大小写、数字或符号组合。
