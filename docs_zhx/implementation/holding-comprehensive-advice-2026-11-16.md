## 2. 实施原则

Python继续提供公共评分、预测、诊断与资料依据；Java继续处理本人持仓、规则和建议留档；Vue负责简洁展示。个人订单、金额等不为方便分析而整体发送到公共预测服务。

先检查已有接口能否提供所需字段，再决定新增字段或只读接口。第一版不新增全市场采集，不重跑所有评分预测，不接自动交易，不另建建议定时任务。

新判断与旧判断分开标识。数据库只在现有结构确实无法容纳时增加兼容字段或迁移；不得预先覆盖旧报告、修改旧版本配置或变更其回放含义。

## 3. 分步实施

### 第一步：核对当前数据和接口

只读读取绑定本人账号的正份额持仓，逐只列出：最新净值、评分期及完整程度、四周期结果和适用日期、诊断状态、个人规则、待确认订单、有效定投和费用可用情况。

核对现有正式第二版预测如何通过Java接口返回，特别检查：暂不判断、有条件半年展望、日期未核实、旧结果和失败尝试。不能只检查旧三分类字段兼容性。

输出逐基金可用性清单，明确本次读取时间。11月16日历史统计只作对照。记录只保留必要摘要，不复制密钥或完整私人账本。

验收出口：能够解释每只基金现阶段可以判断哪些问题、缺什么，以及缺项是否影响动作；确认用于首只验证的基金，不能悄悄以容易完成的基金替代原样本。

### 第二步：确定可检查的判断规则与输入

形成按基金类型和问题划分的必要输入表，明确以下内容后再编码：

- 每类资料适用日期、过期条件及无法确认日期时的处理。
- 哪些缺项阻止判断，哪些只限制结论，以及各自原因。
- 四周期各自用途和发生分歧时的取舍要求。
- 评分分项及诊断如何影响长期持有理由，避免总分直接决定买卖。
- 个人规则触发与已有判断冲突时的优先关系。
- 同一来源事件的识别、去重与引用方式。
- 展示动作与内部字段映射；持有附加“暂缓加仓”和独立“暂不判断”的区别。

建议输入在现有保存结构上扩展：资料可用性、评分依据、分周期判断、持仓与规则、订单及定投摘要、执行限制。具体字段名以检查现有接口后的设计为准，不在本计划中假定不存在的接口已经可用。

验收出口：规则能对关键场景给出可解释、可重复的结果，不依赖临时填充权重或自由发挥的结论。

### 第三步：实现单基金生成与留档

优先复用 `DecisionServiceV2` 入口及报告仓储，新增版本独立处理新判断。生成过程分为资料检查、三个业务问题判断、动作形成、操作条件检查、保存与读回。

生成前取得同一次个人状态视图；保存前检查持仓、规则和相关订单是否变化。发生影响结论的变化时重新读取并重算，或返回需重试，不把前后不同状态混成一份当前报告。不用长时间账户锁包住公共资料读取。

查看页面只读取保存结果。手动生成优先使用适用的正式结果；不默认触发全量资料更新或全部预测重算。明确生成请求的重复处理方式，输入未变不反复追加相同报告。

保存实际输入、来源和适用条件。新报告失败或资料不足保留原因，旧有效原文仍可读取。对“报告过期”和“本人状态改变”分别判断，不机械沿用现有固定一天有效期。

验收出口：一只实际持仓能生成并读回完整报告，能够追查理由；交易、计划、份额和成本未被生成动作修改。

### 第四步：调整抽屉与完整依据页面

遵守 `01-vue/DESIGN.md` 与功能保全清单。抽屉展示结论、关键理由、主要限制、资料日期和完整依据入口。完整页面展示分歧、反对因素、缺项影响、本人操作条件、重新评估条件及历史。

区分读取中、生成中、没有报告、暂不判断、生成失败、历史已过期和当前可用。生成期间防止重复点击；保存后以服务端读回结果为准。基金切换后迟到响应不得显示到另一只基金。

移除日常页面中的模型身份、权重、版本、错误码和请求标识展示；底层保存与排障日志保留必要追溯信息。旧历史显示业务内容，不删除旧记录。

验收出口：用户无需理解后台实现即可看清建议、限制和下一次复核条件；原入口与窄屏操作正常。

### 第五步：扩大到当前持仓并整理验收

首只打通后按当前正份额持仓动态核对，不固定29只或30只。先进行受控逐只验证，避免无必要的大批量读写。自动生成接入如需新增调度，另行说明范围，不随手恢复旧任务。

第一版继续展示已有预测到期核验，明确这不是综合建议有效率。综合动作评价另立规则后实施，不能套用旧方向命中率。

## 4. 必须覆盖的验证场景

| 场景 | 应有结果 |
|---|---|
| 只有一个有效周期 | 不经重新分配权重伪装完整；按缺项影响决定暂缓判断或限定结论 |
| 一日、五日下跌，长期有支持 | 解释近期压力与长期依据，不自动判全部卖出 |
| 半年仅有条件展望或结束日期未核 | 保留条件，不当成确定期限方向 |
| 评分新期未完成 | 标明实际评分期，不冒充最新，不以未知补零 |
| 基金评分高但近期风险明确 | 不直接给买入；说明不同问题的取舍 |
| 已确认止盈或回撤规则触发 | 明确提示及影响，不自动下单 |
| 已有待买订单和运行中定投 | 合并考虑操作安排，不重复建议相同投入 |
| 待卖冻结或份额全部冻结 | 不重复扣减，不建议立即卖出不可用份额 |
| 无真实持有批次或费率不齐 | 不给精确赎回费、金额或份额 |
| 同一公告进入评分、诊断和预测 | 引用可追溯且不重复放大 |
| 生成中持仓、规则或订单改变 | 重读重算或提示重试，不保存混合状态 |
| 清仓、空持仓、无权限或其他账号 | 停止本轮新增，保留可授权读取的历史，不串号 |
| 失败、重复点击、刷新与切换基金 | 状态正确，重复请求受控，读取不生成，迟到响应不串基金 |
| 旧报告与新报告同时存在 | 原文、旧链接及旧含义保留，版本不混用 |
| 新存储错误 | 停止写入，保留已有数据并报告 |

### 本次确定的首版规则

1. 不对涨跌票数加权。基金质量依据要求本基金正式完整有效评分；保留考察日及分项，旧考察期不冒充新期。部分、失效、撤回、来源失败或日期不成立时暂不作完整判断。
2. 常规操作方向要求五日与二十日均有当前区间、来源时刻不晚于生成时刻、正反依据及重新评估条件完整的明确方向；持仓净值至少覆盖分析基准日。重复周期、其他基金、已结束、未开始和暂不判断均不补零或重新分权。
3. 一日仅作为近期解释；过15点的旧区间仅供回看。半年条件展望保存为背景，不投票。五日与二十日均偏下、且没有可用的确定日期半年偏上时，提出“考虑减仓”，不直接退出；其他可判断情况暂为“继续持有、暂缓加仓”，解释分歧。
4. 首版没有完整个人资金和风险承受信息，也没有足够结构化证据确认持有理由彻底失效，因此不自动给加仓或全部退出；不以总分代替这些判断。将来增加这些动作须补齐必要输入表及验证，不能仅调阈值。
5. 本人已确认规则可独立产生复核减仓提示，即使公共输入不足仍明确列出缺项。止盈线与回撤线沿用现有草案和保存契约的“小数比例”，当前回撤必须有与持仓净值同日的明确结构化值；不得沿用旧综合代码中的百分比假设。
6. 待卖或无可卖份额时暂缓重复操作；待买和ACTIVE定投单列提醒，不改计划。未核齐开放、逐笔持有期限和费用时不提供精确数量。行业覆盖与完整现金未知继续披露。
7. 操作判断最迟适用至下一个北京时间自然日零点；这只是复核上限，不声称源资料有效期都相同。本人状态变化即需重看；打开单只最新建议时还会只读核对评分与正式分析是否变化。
8. 新记录使用独立版本，复用现有报告表，无数据库迁移。资料不足使用独立业务状态、动作空值；与真正读取失败分开。旧版本原文、历史和回放规则保留。旧固定比例效果评价排除新建议，明确两者统计范围，防止套用旧交易比例。
