# 收益独立更新与历史补齐

日期：2026-11-11。用户明确授权拆开收益更新、定投下单和订单结算，补齐可计算的历史收益，净值更新后继续更新收益。

## 运行边界

- `dev.ps1` 开启 `simulation.valuation.enabled`，账号来自既有 `03-python/.local-runs/automation-owner/account.json`。每分钟检查一次实际持仓起点、已确认成交、公共行情及官方日历版本；无变化不重复写收益。不使用固定基金名单或关注列表替代。
- `simulation.settlement.enabled=false` 明确关闭旧定投与结算定时入口，旧长延迟同时保留；手动接口仍在。没有恢复训练、提醒、交易定时处理、归档、清理或全盘核验。
- 新更新器不依赖原交易服务或原调度器；只使用账户现有期初持仓和 `CONFIRMED` 成交。`PENDING` 买卖不执行，待卖冻结继续读取订单现状。
- 与旧结算共用数据库全局互斥锁，写每只基金时再锁本人账户，防止与手动操作交错。一次行情失败保留既有收益、重试且不推进完成水位；存储错误停止后续写入。

## 计算和保存

- 共用原十进制账务和分红、连续交易日规则，新增只估值入口。已确认成交使用原成交份额、成本、费用和净额，不用当前费率重算，不确认订单；成交参考净值更正时转待核对。
- 持仓期初余额始终保留。保存前核对份额、成本、投入、收回和已实现收益不变；不一致时停止该基金更新。
- 新 `Valuation` 契约仅含持仓投影与每日收益，没有订单执行结果或交易流水。独立保存入口只更新 `sim_position`、`sim_daily_valuation`，不改订单、计划、期次、交易流水或期初余额。
- V32 仅增加 `sim_position.valuation_state`。保存实际读取到的净值日期及缺失原因，不删除历史数据。来源撤回的旧日期保留，但在收益查询中排除，不能继续冒充有效净值。
- 兼容既有 JSON 数组形式的日期，避免把期初日期当字符串强转失败。没有重新导入、替换或初始化现有 Docker 数据卷。

## 页面状态

- 已核验来源中缺少最新日期：等待该日净值。不据此宣称基金管理人尚未公布。
- 有该日净值但还没有收益：收益待更新。
- 中间日期缺净值：该日净值缺失；已有投影但缺连续日收益：历史收益待补。
- 行情暂时读不到：通用等待提示，不误判净值尚未公布，也不清除既有待核对问题。
- 期初日：不计当日收益，不虚构录入之前的收益。后续完整日期可形成期间合计。
- 部分基金可计算：展示已完成数量和已知部分，不当作整个账户的完整合计。
- 分红、成交证据或日历待核对：保留未知并在基金构成中说明实际原因。2027 年以后的日历仍只接受已核验官方安排。
